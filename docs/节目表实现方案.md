# 节目表（EPG）实现说明

本文描述当前代码中 EPG 的实际实现，取代早期的设计稿。

## 1. 功能范围

- 数据源：XMLTV 格式节目表，支持 `.gz` 压缩包。
- 展示：频道列表、单频道节目表、当前正在播放、节目分类、分类下频道。
- 更新：手动刷新 + 每天定时刷新。
- 缓存：内存缓存 + 程序目录下的 `epg_cache.json` 磁盘缓存。

## 2. 配置

配置位于程序目录的 `recsettings.json`：

```json
{
  "epg": {
    "url": "http://epg.51zmt.top:8000/e.xml.gz",
    "updateTime": "08:00",
    "cacheDurationHours": 24
  }
}
```

- `url`：XMLTV 地址，以 `.gz` 结尾时自动解压。
- `updateTime`：每日自动更新时间，本地时间，格式 `HH:mm`。
- `cacheDurationHours`：目前仅保留在配置模型中，未参与缓存逻辑。

## 3. 后端结构

| 组件 | 职责 |
| --- | --- |
| `EpgService` | 持有内存数据，负责磁盘缓存读写、首次懒加载、下载并解析 EPG |
| `XmlTvParserService` | 使用 `XmlReader` 流式解析 XMLTV |
| `CachedEpgService` | `IEpgService` 的缓存装饰器，基于 `IMemoryCache` |
| `EpgUpdateBackgroundService` | 每天按 `updateTime` 触发一次刷新，失败后 1 小时重试 |
| `EpgApiEndpoints` | 注册 `/api/epg/*` 路由 |

相关文件：

- `src/backend/Server/Services/Epg/`
- `src/backend/Shared/EpgModels.cs`
- `src/backend/Shared/AppConfig.cs`
- `src/backend/Shared/RtspJsonContext.cs`

## 4. 数据流

1. 程序启动时，`EpgService` 尝试读取 `epg_cache.json` 到内存。
2. 首次访问 EPG 接口且内存无数据时，同步执行一次完整刷新：下载 → 解压 → 解析 → 保存到内存和磁盘。
3. 手动刷新或定时刷新时，重新执行完整下载和解析，用新数据整体替换旧数据。
4. 下载使用独立的 `HttpClient`，超时 10 分钟；刷新通过 `SemaphoreSlim` 串行化，已有刷新在进行时直接跳过本次请求。

解析规则：

- 时间支持 `yyyyMMddHHmmss`、`yyyyMMddHHmm`、`yyyyMMdd`，带 `+0800` 这类偏移时先转 UTC 再转本地时间。
- 频道名和节目名优先取 `lang="zh"` 的 `display-name` / `title`。
- 节目 ID 由 `channelId_开始时间` 生成；节目按开始时间排序。
- 节目中的分类会汇总到所属频道，供分类页使用。
- 支持解析图标、副标题、简介、剧集号、星级、分级、首播/新节目/重播/字幕/高清等标记。

## 5. 缓存策略

- `EpgDataCache` 常驻内存，包含频道列表和按频道分组的节目字典。
- 磁盘文件：程序目录下的 `epg_cache.json`，刷新成功后整体写回。
- `IMemoryCache` 缓存键：
  - `epg_all_channels`：15 分钟滑动过期。
  - `epg_channel_programs_{channelId}`：5 分钟滑动过期。
  - `epg_categories`、`epg_channels_by_category_{category}`：15 分钟滑动过期。
  - 当前节目和最后更新时间不缓存，直接实时计算。

## 6. HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/epg/channels` | 所有频道 |
| GET | `/api/epg/channels/{channelId}/programs` | 指定频道的完整节目表 |
| GET | `/api/epg/current` | 各频道当前节目，含进度和剩余分钟 |
| GET | `/api/epg/categories` | 所有分类 |
| GET | `/api/epg/categories/{category}/channels` | 指定分类下的频道 |
| POST | `/api/epg/refresh` | 立即执行一次完整刷新 |
| GET | `/api/epg/status` | 最后更新时间 |

接口异常统一返回 500，响应体为 `{ "message": "..." }`；启用 Basic Auth 时同样受全局认证保护。

## 7. 前端

路由位于 `src/frontend/src/features/epg/`：

| 路径 | 页面 |
| --- | --- |
| `/epg` | 概览：频道卡片 + 当前节目进度 |
| `/epg/channels` | 所有频道 |
| `/epg/channels/:channelId` | 单频道节目表，可切换最近 4 天，自动定位当前节目 |
| `/epg/current` | 当前播放 |
| `/epg/categories` | 节目分类 |
| `/epg/categories/:category` | 分类下频道 |

- `EpgProvider` 统一管理频道、分类、当前节目状态，进入 EPG 页面时并行加载。
- 单频道节目表按需请求。
- 当前节目会在节目结束后 1–15 秒内自动刷新，每 5 秒检查一次，并有 10 秒冷却避免频繁请求。
- 概览页点击频道进入详情；详情页顶部提供“返回概览”。
- “刷新节目表”按钮带二次确认，刷新期间显示加载遮罩。

## 8. 已知限制

- `/epg/categories/:category` 页面尚未调用分类频道接口，当前只是取频道列表前 4 个作为占位展示。
- `/epg/channels`、`/epg/current`、`/epg/categories` 路由已存在，但界面没有入口链接，只能直接访问 URL。
- 刷新时 `CachedEpgService.ClearAllCache` 先移除 `epg_all_channels` 再读取它来清理子缓存，导致频道节目表和分类频道缓存实际不会被清除，刷新后可能短暂保留旧数据直到滑动过期。
- EPG 数据全量常驻内存，每次刷新都重新下载并解析完整文件，没有增量更新。
